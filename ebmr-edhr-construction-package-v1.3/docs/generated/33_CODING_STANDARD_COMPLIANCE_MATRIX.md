## Non-negotiable coding rules

- TypeScript `strict` everywhere; no `any` in regulated paths.
- Python type hints and mypy on the Frappe app.
- Decimal arithmetic for regulated quantities; binary floats prohibited (Doc 110).
- UTC-aware time only; server-assigned timestamps for regulated events.
- Typed errors mapped to registry error codes; no free-text-only failures.
- Structured, redacted logging; no PII or secrets in logs.
- Parameterised SQL only; no string-built queries.
- Short transaction boundaries; no external I/O inside a regulated transaction.
- No dynamic execution (`eval`, customer-supplied code) in regulated paths.
- No Frappe/ERPNext core edits.
- No direct database access to another service's schema.
