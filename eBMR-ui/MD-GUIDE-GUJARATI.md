# Medical Device (MD) — સંપૂર્ણ ગાઈડ, સ્ક્રીન બાય સ્ક્રીન

આ ડોક્યુમેન્ટ એ લોકો માટે છે જેમને eBMR વિશે કંઈ જ ખબર નથી. **Medical Device વિભાગની બધી જ 31 સ્ક્રીન** એક પછી એક સમજાવેલી છે — દરેક સ્ક્રીન શું છે, કોણ વાપરે છે, એમાં શું દેખાય છે, અને એની પ્રોસેસ શું છે.

**દરેક સ્ક્રીન માટે એક જ ફોર્મેટ વાપર્યું છે:**
- **કોણ વાપરે** — કઈ વ્યક્તિ/ભૂમિકા
- **આ શું છે** — સ્ક્રીનનો હેતુ, એક લીટીમાં
- **શું દેખાય છે** — સ્ક્રીન પર ખરેખર શું છે
- **પ્રોસેસ** — સ્ટેપ બાય સ્ટેપ શું થાય
- **ડેમોમાં ખાસ જોવા જેવું** — આ પ્રીવ્યુમાં કઈ ખાસ વાત બતાવી છે

## 1. eBMR શું છે?

જ્યારે કોઈ કંપની મેડિકલ ડિવાઇસ બનાવે છે, ત્યારે **દરેક સ્ટેપનો રેકોર્ડ** રાખવો કાયદેસર ફરજિયાત છે (અમેરિકામાં FDA ના 21 CFR 820 નિયમો પ્રમાણે) — કોણે શું કર્યું, ક્યારે, કયું મશીન વાપર્યું, ટેસ્ટ પાસ થયો કે નહીં.

પહેલા આ બધું **કાગળ પર** લખાતું. ડિવાઇસ માટે એ રેકોર્ડને **DHR (Device History Record)** કહેવાય. **eBMR** એટલે એ જ કામ **કમ્પ્યુટર પર** — જ્યાં કોઈ રેકોર્ડ ડિલીટ કે ચૂપચાપ બદલી ના શકે.

**અગત્યની વાત:** આ eBMR-ui ફક્ત **ડિઝાઈન પ્રીવ્યુ** છે. પાછળ કોઈ સાચું ડેટાબેઝ કે સર્વર નથી. બટન દબાવવાથી કંઈ સેવ નથી થતું — ફક્ત સ્ક્રીન કેવી દેખાશે એ બતાવે છે.

## 3. Medical Device (MD) એટલે શું?

**MD = Medical Device** — દર્દીની સારવારમાં વપરાતી વસ્તુ, પણ એ **દવા નથી**. આ ડેમોમાં: **Infusion Set IS-200** (ડ્રિપ ચઢાવવાનો સેટ), યુનિટ નંબર **SN-88213**, બનતું સ્થળ **Acme MedTech · Site 2 · Line B**.

**દવા અને ડિવાઇસ વચ્ચેનો મુખ્ય ફરક:**

| | દવા (PH) | ડિવાઇસ (MD) |
|---|---|---|
| કઈ રીતે ગણાય? | **Batch** (લાખો ટેબ્લેટ એકસાથે) | **Unit / Serial** (દરેક નંગનો પોતાનો નંબર) |
| પ્રોબ્લેમને શું કહેવાય? | Deviation / OOS / Investigation | **Nonconformance (NC)** |
| ફરી સુધારી શકાય? | **ના** — v1 માં rework નથી | **હા** — Rework થઈ શકે (મંજૂર રસ્તો હોય તો) |
| છેલ્લી મંજૂરી કોણ આપે? | Quality Unit (QU) | **Device Quality** |

**યાદ રાખવાનો નિયમ:** ડિવાઇસની સ્ક્રીન પર ક્યારેય "Deviation" શબ્દ નહીં દેખાય, અને દવાની સ્ક્રીન પર ક્યારેય "Rework" બટન નહીં દેખાય. બંનેના કાયદા જુદા છે, એટલે ભાષા પણ જુદી રાખી છે.

### સ્ક્રીન 3 — Master catalogue (`md/masters/catalogue.html`)

**કોણ વાપરે:** S. Rao (Master Author)

**આ શું છે:** બધા માસ્ટરની યાદી અને એમની **વંશાવળી (lineage)** — કઈ આવૃત્તિ પછી કઈ આવી.

**શું દેખાય છે:** ઉપર ટેબલમાં 4 માસ્ટર:
- **IS-200 Rev C** — Effective (અત્યારે ચાલુ), 01 Jun 2026 થી
- **IS-200 Rev D** — Under review (નવી, હજુ ચેક થાય છે)
- **IS-140 Rev G** — Effective (બીજું પ્રોડક્ટ)
- **IS-090 Rev C** — Obsolete (જૂનું, હવે નથી વપરાતું)

### સ્ક્રીન 17 — Hold/issue (`md/production/hold.html`)

**કોણ વાપરે:** કોઈ પણ ટ્રેઈન થયેલી વ્યક્તિ

**આ શું છે:** કંઈ પણ ખોટું લાગે તો **તરત કામ રોકવાની** સ્ક્રીન. દરેક સ્ક્રીન પર ઉપર લાલ **"Stop / Raise Issue"** બટન હોય છે, જે અહીં લાવે.

**ડેમોમાં ખાસ જોવા જેવું:**
- Affected scope માં લખેલું છે "**SN-88213 only** — Line B not otherwise affected". અસ્પષ્ટ "આ એરિયામાં પ્રોબ્લેમ" નહીં ચાલે — **ચોક્કસ** કહેવું પડે.
- નીચે લખ્યું છે: **પ્રોબ્લેમ ઉઠાવવો અને એનો નિર્ણય લેવો બે અલગ કામ છે.** તમે issue ઉઠાવી શકો, પણ એનો નિર્ણય તમે ના લઈ શકો (સિવાય કે તમારી પાસે એ સત્તા અલગથી હોય).

## 9. વિસ્તાર — Device Quality (3 સ્ક્રીન) ⭐

**Device Quality એટલે શું?** આ **ક્વોલિટી વિભાગનું** કામ છે, પ્રોડક્શનનું નહીં. પ્રોડક્શન બનાવે, ક્વોલિટી નક્કી કરે કે એ વાપરવા લાયક છે કે નહીં. **બંને અલગ લોકો હોવા જ જોઈએ.**

### સ્ક્રીન 22 — Nonconformance (`md/quality/nonconformance.html`)

**કોણ વાપરે:** R. Oduya (Device Quality)

**આ શું છે:** ટેસ્ટ ફેલ થયો (NC-2231), હવે **એ યુનિટનું શું કરવું** એ નક્કી કરવાની સ્ક્રીન. આને "disposition" (નિકાલ) કહેવાય.

**શું દેખાય છે:** ઉપર failure record —
- **Affected unit:** SN-88213 only
- **Failed step:** OP-030 Final functional test
- **Original result:** Leak decay pressure drop 3.2 kPa against a limit of ≤ 2.0 kPa

નીચે **Disposition** પસંદગી, ત્રણ વિકલ્પ:

| વિકલ્પ | અર્થ | ક્યારે |
|---|---|---|
| **Scrap** | ફેંકી દો | સુધારી ના શકાય ત્યારે |
| **Rework** ← ડેમોમાં પસંદ | સુધારીને ફરી ટેસ્ટ કરો | **ફક્ત ત્યારે જ** જ્યારે એના માટે મંજૂર થયેલી લેખિત સૂચના હોય (અહીં: **IS-200-RWK-02 v1**) |
| **Use-as-is** | જેમ છે તેમ વાપરો | લેખિત justification ફરજિયાત |

નીચે ચેકબોક્સ: "નવું linked execution બનશે — મૂળ ફેલ્યોર દેખાતું રહેશે, બદલાશે નહીં".

**પ્રોસેસ:** ફેલ્યોર જુઓ → ત્રણમાંથી એક વિકલ્પ પસંદ કરો → કારણ/સૂચના લખો → નિર્ણય નોંધો.

| Assess (તપાસ) | ✅ પૂરું — કારણ એક packaging run પૂરતું મર્યાદિત |
| **Authorize** | 🔵 ચાલુ — release authority ની સહી બાકી |
| Verify | ⬜ બાકી |
| Close | ⬜ બાકી |

**પ્રોસેસ:** ફરિયાદ આવે → અસર તપાસો → સુધારો મંજૂર કરો → ચકાસો → બંધ કરો.

**ડેમોમાં ખાસ જોવા જેવું:** સૌથી નીચે લખ્યું છે: *"The original released record is never overwritten — the amendment links to it."* એટલે **જૂનો છૂટેલો રેકોર્ડ ક્યારેય બદલાતો નથી**; સુધારો એની સાથે જોડાય છે, પોતાની અલગ સહી સાથે. કારણ — બે વર્ષ પછી ઓડિટમાં "એ વખતે શું જાણતા હતા" અને "પછી શું ખબર પડી" બંને દેખાવું જોઈએ.

## 12. અત્યારે આટલું બધું "બ્લોક" કેમ દેખાય છે?

આ ડેમોમાં **ઘણાં મુખ્ય બટન ગ્રે (દબાવી ના શકાય)** છે. **આ ભૂલ નથી — ઈરાદાપૂર્વક છે.**

દરેક બ્લોક થયેલા બટન સાથે **તાળાનું નિશાન 🔒 અને કારણ** લખેલું હોય છે:

| સ્ક્રીન | બટન | કારણ |
|---|---|---|
| Masters admission | Approve admission | 2 હકીકતો બાકી |
| Masters validation | Check complete | 1 કોમેન્ટ બાકી |
| Masters approval | Approve & schedule | cutover conflict |
| Readiness | Mark Ready | 2 ચેક બાકી |
| Execution | Accept anyway | **જાણી જોઈને આપ્યું જ નથી** |
| Equipment | Use equipment | EQ-7710 calibration overdue |
| Completion | Attest complete | NC-2231 + 1 સહી બાકી |
| Interfaces | Accept migration | ગ્રાહકની મંજૂરી જોઈએ |

**આ જ eBMR નો સૌથી મોટો ફાયદો છે:** સિસ્ટમ ફક્ત "ના" નથી પાડતી — **શા માટે ના પાડી અને હવે શું કરવું** એ પણ કહે છે. કાગળ પર તો કોઈ ઉતાવળમાં કે દબાણમાં આગળ સહી કરી દે; અહીં એ શક્ય જ નથી.

## 14. શબ્દકોશ (Glossary)

| શબ્દ | અર્થ |
|---|---|
| **DHR** | Device History Record — એક ડિવાઇસ કેવી રીતે બન્યું એનો સંપૂર્ણ રેકોર્ડ |
| **Master** | ડિવાઇસ બનાવવાની મંજૂર થયેલી સૂચનાઓ |
| **Snapshot** | મંજૂર માસ્ટરની જડ કોપી, જે બદલી ના શકાય |
| **Governing** | અત્યારે કાયદેસર ચાલુ આવૃત્તિ |
| **NC (Nonconformance)** | ડિવાઇસમાં કંઈક નિયમ મુજબ ના થયું |
| **Disposition** | NC નો નિર્ણય — Scrap / Rework / Use-as-is |
| **Rework** | સુધારીને ફરી બનાવવું (ફક્ત ડિવાઇસમાં, દવામાં નહીં) |
| **SoD** | Segregation of Duties — કામની વહેંચણી, એક વ્યક્તિ બધું ના કરે |
| **UDI** | Unique Device Identification — ડિવાઇસનો દુનિયાભરમાં યુનિક નંબર |
| **Genealogy** | કયો માલ, કયા લોટમાંથી, કયા મશીન પર વપરાયો |
| **Exception-first** | પહેલાં ફક્ત પ્રોબ્લેમવાળી જગ્યા બતાવવી |
| **Digest** | રેકોર્ડનો ડિજિટલ ફિંગરપ્રિન્ટ (sha256…) — છેડછાડ પકડે |
| **Stale** | બહુ જૂનું, હવે ભરોસાપાત્ર નથી |
| **Superseded** | બદલાઈ ગયું, પણ ભૂંસાયું નથી |
| **Part 11** | 21 CFR Part 11 — ઇલેક્ટ્રોનિક રેકોર્ડ અને સહીનો FDA નિયમ |

## 15. ટૂંકમાં (Summary)

- **MD** = મેડિકલ ડિવાઇસ — દા.ત. Infusion Set IS-200, યુનિટ SN-88213.
- **31 સ્ક્રીન**, 6 વિસ્તારમાં વહેંચાયેલી, 7 જુદી જુદી ભૂમિકા.
- ગણતરી **યુનિટ/સિરિયલ** થી (બેચથી નહીં); પ્રોબ્લેમને **Nonconformance** કહેવાય; **Rework થઈ શકે**; છેલ્લી મંજૂરી **Device Quality** આપે.
- આખો પ્રવાહ: Masters (સૂચનાઓ) → Issuance (યુનિટ ઈશ્યુ) → Production (બનાવો + પુરાવો) → Device Quality (નિર્ણય + રિવ્યુ + Release) → Records (કાયમી રેકોર્ડ).
- આ ડેમોની વાર્તા: **ટેસ્ટ ફેલ થયો (3.2 vs ≤2.0 kPa) → NC-2231 ખૂલ્યું → Rework નક્કી થયું → રિવ્યુ → Release**.
- ઘણાં બટન ગ્રે છે — એ સિસ્ટમ **સાચું** કામ કરે છે એની નિશાની છે, ભૂલ નથી.
- આ ફક્ત **ડિઝાઈન પ્રીવ્યુ** છે — પાછળ સાચો ડેટાબેઝ કે સર્વર નથી.
